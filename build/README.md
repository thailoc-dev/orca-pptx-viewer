# Building Presentation Viewer

`../editor/index.html` is generated from the source here. Orca loads it in a sandboxed frame
whose CSP allows inline scripts and styles, and `data:` images and fonts only; network, workers
and eval are blocked. Everything is bundled into that one file.

```sh
npm ci --ignore-scripts
npm run build
npm test
```

Tests drive the editor in headless Chromium through a harness that reproduces Orca's
`sandbox="allow-scripts"` frame, CSP, theme tokens and document API, with a deck generated by
`pptxgenjs`. Install the browser with `npx playwright-core install chromium-headless-shell` if
needed. Google Chrome's headless mode is not used: it drops clicks near the bottom of the frame.

## How the renderer fits the sandbox

| File | Purpose |
| --- | --- |
| `src/editor.js`, `src/editor.css` | Frame API, versions, navigation, zoom, links, controls |
| `src/csp-shims.js` | Turns the renderer's `blob:` URLs into `data:` URLs the CSP accepts |
| `src/set-immediate.js`, `src/no-node-stream.js` | CSP-safe stand-ins for JSZip's polyfills |
| `src/document-message.js` | Versioned byte-document validation and the size cap |
| `test/harness.mjs`, `test/fixture.mjs` | Orca-like sandbox and a synthetic deck |

- The renderer creates `blob:` URLs for pictures. `csp-shims.js` makes `Blob` remember the bytes
  it was built from, so `URL.createObjectURL` can return an equivalent `data:` URL synchronously.
- JSZip is bundled from its source entry (its prebundled browser file carries a `new Function`
  fallback); the build refuses any `eval` or `new Function` in the output.
- PDF.js fallback previews for EMF pictures are disabled (`pdfjs: false`): they need workers.
- External pictures and media are blocked (`externalMedia: 'block'`).
